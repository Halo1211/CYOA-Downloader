## Intentional behavior differences (Rust is equal or better; each is covered by a test)

1. **DL-5 secrets:** stored in the keyring by default; legacy plaintext is migrated into the keyring and never written back out.
2. **DL-8 paths:** any link or junction component inside the output root is rejected. This is stricter than Python.
3. **Checkpoint `get`:** always re-hashes, because NTFS ChangeTime cannot be read without `unsafe`.
4. **Parse, out-of-range floats (`1e400`):** Python emits the invalid JSON token `Infinity`; Rust emits `null`, which is valid JSON.
5. **Parse, non-UTF-8 decoding:** Python's chardet misdetected latin-1 and Shift-JIS samples (`"ZÈZ"`, `"𣲚塲"`); Rust's fixed fallback chain decodes them correctly (`"été"`, `"日本"`).
6. **HTTP:** connections go only to DNS answers vetted by the policy (closes the Python rebinding window, SEC-6). Downloads have a byte cap (SEC-4).
7. **Copy/report APIs:** return structured reports instead of logging and skipping.
8. **F-028 browser (s8):** Chrome/Edge/Brave over CDP replaces Playwright's bundled Chromium and Selenium (D3); no browser download. Captured runtime responses are kept in memory under the same bounds as Python's spool files (2 MiB each, 32 MiB, 128 entries). Popups are closed through CDP target events; redirect (3xx) responses are not "observed" (CDP reports only final responses), the final asset is. A browser launched under a home without `AppData\Local` gets a private `USERPROFILE` (Chromium otherwise refuses DevTools). Stale `cyoa-browser-*` temp profiles older than 1 h are swept at the next launch. The mirror also retries transport errors (not only HTTP >= 400) through the browser in Auto/Browser; the original error is recorded when the browser also fails.

Known parity gaps:
- ZIP duplicate detection uses `to_lowercase`, where Python uses `casefold` (ß).
- Some settings edge numerics: huge ints, NaN, unpaired surrogates.
- History has no inter-process file lock.

## Security deviations (2026-11-21, safer than Python)
- AI deep-scan JS collection is bounded (2000 files, 64 MiB total); Python reads all JS files. Identical output on normal sites.
- Settings export redacts nested secret keys, URL userinfo and secret query parameters; Python filters top-level key names only.
- Browser traffic goes through a loopback relay that enforces the destination policy and holds the proxy credentials; Python (Playwright) answered proxy challenges inside the browser and did not check destinations. HTTPS/SOCKS proxies with credentials are not supported for the browser strategy (Python supported them, which exposed the credentials).
- ZIP image de-duplication picks the representative deterministically (sorted asset path); Python's choice depends on thread timing. Same image content, possibly different file names for duplicates.
- TLS: on Windows the HTTP client uses the native Schannel stack (like curl); Python uses OpenSSL through requests. Both are accepted by sites that block unusual TLS fingerprints. Website mirror requests send Python's session headers and retry like urllib3 (3x, Retry-After, per-hop budget).
